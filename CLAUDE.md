# knigopis-p2p

Переделка knigopis.com (список прочитанных книг) так, чтобы сайт не зависел от одного хостинга и сторонних входов.
Статус: **работает на https://www.knigopis.com** (с 2026-11-02; прежний адрес демо knigopis.bizibah.com перенаправляется туда). План и открытые вопросы — в `TODO.md`.
Код: https://github.com/knigopis/knigopis-p2p (с 2026-11-02, перенесён от `gurov` — старые адреса перенаправляются;
приватный до конца настройки, потом станет публичным; ветка `master`). `gurov` — соавтор.

## Старые данные (repo2)

- Раскладка: `users/<первые 3 символа id>/<id>/<id>.json`, рядом `books/<bookId>.json` и `wishes/<wishId>.json`.
- id пользователя = `<uid>-<provider>`, например `83820536-yandex`. У локальных — `<login>-local`, и login бывает email (есть `@` и `.`).
- Пользователь: `id, lang, nickname, photo, profile, identity, booksCount, subscriptions, createdAt, updatedAt`.
  `subscriptions` = `{ "<userId>": <booksCount на момент просмотра> }`, лежат в публичном JSON.
- Книга: `id, userId, createdAt, updatedAt, title, author, readDay, readMonth, readYear, notes` (даты — строки, бывают пустыми).
  Желание: `id, userId, createdAt, updatedAt, title, author, priority, notes`.
- **`auth.csv` — bcrypt-хэши паролей локальных аккаунтов в открытом доступе.** Упаковка архива его не читает.
- На 2026-10-30: 4276 пользователей, 31 077 книг, 6169 желаний; ≥100 пользователей с подписками.
- Старый адрес профиля: `/#/<ник>/books?u=<userId>&y=<год>`. PWA перенаправляет его на `/archive/<userId>` (`src/main.tsx`).
- Основной адрес — **`www.knigopis.com`**, корень перенаправляется на www, как у старого сайта. Адрес не менять:
  смена разлогинивает всех (ключ привязан к origin). В `known-relays.json` — `wss://www.knigopis.com`: WebSocket
  по редиректу не переходит.

## Устройство прототипа

- **Клиент:** PWA на Preact 11 + preact-iso + @preact/signals + nostr-tools + Vite 8 + vite-plugin-pwa. Бэкенда нет.
  - `src/lib/` — данные:
    - `account` — ключ в localStorage, nsec, ссылка входа `/login#nsec…`;
    - `nostr` — пул, `query`/`queryAll` (страницы назад по `until`), `publish`; список relay в localStorage —
      только правки пользователя (`added`/`removed`) к списку по умолчанию, чтобы новые узлы из релизов доходили до всех;
    - `records` — книги, желания, заявки ↔ события;
    - `legacy` — архив;
    - `importer` — перенос;
    - `profiles` (kind 0), `follows` (kind 3).
  - **Ссылка на пользователя** — `/u/<первые 16 hex ключа>` (старые `/u/npub1…` тоже работают). Relay по началу
    ключа не ищут (strfry: «filter item too small»), поэтому профиль несёт тег `u` с этими 16 символами: поиск
    `#u`, затем проверка, что ключ правда так начинается. Профиль без тега (сохранённый до 2026-11-02) получает
    его при входе (`ensureShortTag`); до этого короткая ссылка на такого пользователя не открывается.
  - **«Хочу прочитать»** видит только хозяин: на своей странице и в своём архиве (после переноса). Это только
    интерфейс — события не зашифрованы, как и желания в repo2.
  - `src/pages/`, `src/components/` — экраны и общие куски. `BookList` — список по годам с оглавлением.
  - Стили — один файл `src/styles/main.css`, своя система (с 2026-11-02; от v1 остались шапка с текстурой и логотип).
    Шрифты: системный 17px для текста; Literata — заголовки и названия книг (`public/fonts/literata.woff2`, OFL:
    кириллица + латиница, жирность 400–700, оптический размер зафиксирован на 24 — 71 КБ вместо ~130 КБ у Google;
    в предзагрузке SW). Один акцент — синий `--primary`.
  - Главная: слева приветствие, справа «Книгопись переехала» с поиском по архиву; ниже лента «Недавно прочитали»
    и архив (одна книга на человека) + колонка «Почему Книгопись», узлы. Вошедшему — «Что вы прочитали недавно?»,
    панель переезда — только пока он ничего не перенёс. Список книг — как дневник: дата («1 ноября») колонкой слева.
- **Архив:** `scripts/legacy.sh` → `scripts/pack-legacy.mjs` из временного клона repo2 → `public/legacy/` (~30 МБ, 4,3 тыс. файлов):
  - `index.json` — пользователи;
  - `users/<id>.json` — пользователь целиком;
  - `books-index.json` — для поиска по названию, грузится лениво;
  - `latest.json` — для главной: `{users, books, items}`, последние книги с заметками по одной на человека.
  photo/profile/identity выкидываются. Service Worker архив не предзагружает, а кеширует по мере просмотра.
- **Relay:** `relay/` — strfry 1.1.3 (собирается из исходников в `Dockerfile`), `write-policy.py` — плагин:
  - принимает только kind 0, 3, 5, 10002, 31110–31112;
  - требует тег `d` и название;
  - режет частоту по адресу: ведро 3000 событий, +2 в секунду; у IPv6 ведро на сеть /64; полные вёдра забываются;
  - когда свободного места меньше `MIN_FREE_MB` (500), отказывает любой записи, включая синхронизацию.

  Проверки — `python3 relay/test_write_policy.py`.

  `maxFilterLimit = 5000`. Точка входа — `run.sh`: relay плюс, если задан `UPSTREAM`, `strfry sync --dir both`
  с другими узлами раз в `SYNC_INTERVAL`. Синхронизация идёт в том же контейнере: LMDB проверяет читателей по PID.
  С аргументами `run.sh` просто запускает команду strfry (`export`, `sync`…).
- **Узел — один образ** `ghcr.io/knigopis/knigopis-p2p/node` (с 2026-11-02): сайт, архив, strfry и Caddy в одном
  контейнере. `Dockerfile` в корне: цель `node` (по умолчанию) и `relay` (только strfry — для разработки).
  - `node/start.sh` пишет Caddyfile по `.env` и запускает strfry (`run.sh`, от пользователя strfry через su-exec)
    и Caddy (root). Упал любой — контейнер выходит, Docker перезапускает. PID 1 — `tini -g`.
  - Маршруты — `node/routes.caddy`: WebSocket и NIP-11 → strfry на `127.0.0.1:7777` (наружу не виден), `/legacy/*`
    — честный 404, остальное — SPA. strfry получает адрес клиента в `X-Real-IP` (`{client_ip}`).
  - Режимы: свой HTTPS (`DOMAIN`); `BEHIND_PROXY=1` — HTTP на 80, адрес клиента из `X-Forwarded-For` только от
    прокси из частных сетей, `trusted_proxies_strict` (самый правый недоверенный: левые клиент подставит сам).
    `REDIRECT_FROM` — адреса, перенаправляемые на `DOMAIN`.
  - `UPSTREAM` по умолчанию — `src/known-relays.json` на момент сборки минус свой адрес; `none` — без синхронизации.
  - Ограничения в compose-файлах: `mem_limit` 512m (`MEM_LIMIT`), `pids_limit` 256, `cap_drop: ALL` +
    `NET_BIND_SERVICE`, `SETUID`/`SETGID` (su-exec) и `KILL`: без него `start.sh` (root) не может проверять `kill -0`
    процессы strfry — решит, что relay упал, и контейнер будет перезапускаться по кругу.
    **`no-new-privileges` не ставить:** на bizibah (Ubuntu 24.04, ядро 6.8, AppArmor) контейнер с ним не стартует —
    `exec /sbin/tini: operation not permitted`, а локально всё проходило. 2026-11-02 это уронило главный узел.
    Новые ограничения проверять одноразовым контейнером на самом сервере, прежде чем выкладывать.
  - CSP — в `node/routes.caddy`: всё только своё, `connect-src 'self' wss:`. Встроенных скриптов и стилей в сборке нет;
    стили из Preact (`style={{…}}`) идут через CSSOM, CSP их не трогает.
- **Установка узла** (`selfhost/`, инструкция — `selfhost/README.md`): по compose-файлу на случай — `compose.yml`
  (порты 80/443), `compose.proxy.yml` (за своим nginx/Caddy, `127.0.0.1:8080`; пример nginx — `nginx.conf.example`),
  `compose.nginx-proxy.yml`. В `.env` — `DOMAIN`, остальное по желанию (`.env.example`). Обновление —
  `docker compose pull && docker compose up -d`. Все файлы `name: knigopis`, том записей — `relay-data`.
  Отдельные файлы, а не надстройки: Compose v2.20 (как на bizibah) не умеет `!reset` для списка портов.
  - Клиент по умолчанию пишет на свой хост и все узлы из `src/known-relays.json`; новый узел добавляется туда PR
    и в `relays.txt` бота снимков.
  - Синхронизация — сеткой без центра: новый узел сам синхронизируется со всеми известными (`UPSTREAM` по умолчанию,
    см. выше). Sync двусторонний, старым узлам ничего менять не надо. «Главный» узел — только адрес, на который заходят читатели; ключи привязаны
    к origin, поэтому домен должен быть у долгосрочного владельца.
  - Страница сайта `/node` («Свой узел», `src/pages/NodePage.tsx`) — короткая версия инструкции для читателей;
    команды в ней должны совпадать с `selfhost/README.md`. Ссылки на неё — в «Долговечности» на главной и в подвале.
    Адрес репозитория — `REPO_URL` в `src/lib/config.ts`.
- **Бэкап записей** — https://github.com/knigopis/events (работает с 2026-11-02), локально `~/p-erebor/knigopis-events`
  (бот там же, `npm test`; коммиты бота — `git pull` перед правками). GitHub Actions два раза в день читает
  все события со всех узлов из `relays.txt`, проверяет подписи и коммитит последние версии
  в `events/<2 символа>/<pubkey>.jsonl`. Надгробия остаются, kind 5 убирает только старые версии.
  Предохранитель: больше 5000 новых или −10% (и хотя бы −10) — без коммита, запуск падает; `force` в Run workflow. Восстановление — `strfry import`, подделки он отвергает
  (проверено 2026-11-02).
- **Релиз** (`npm run release -- vX.Y.Z`, только из чистого запушенного HEAD) — `knigopis-site.tar.gz` (сайт с архивом)
  и `knigopis-legacy.tar.gz` для зеркал. Опубликованный релиз запускает `.github/workflows/node.yml`: образ узла
  с тегами версии и `latest` (только amd64 — бесплатные ARM-машины GitHub только у публичных репозиториев;
  кеш слоёв — gha; сборка 6–11 минут). Пакет `node` публичный (с 2026-11-02); новый пакет в реестре создаётся
  приватным, видимость меняется только в его настройках под `knigopis`.
  В сборке есть `404.html` (копия `index.html`) — для статических хостингов без SPA-маршрутов.

### События Nostr (номера выбраны, свободны в реестре NIPs на 2026-10)

| kind | что | теги | content |
|---|---|---|---|
| 31110 | книга | `d`, `title`, `author`, `read` (`ГГГГ`/`ГГГГ-ММ`/`ГГГГ-ММ-ДД`), `legacy`=[userId, bookId, createdAt], `alt` | заметки |
| 31111 | желание | `d`, `title`, `author`, `priority`, `legacy`, `alt` | заметки |
| 31112 | заявка на старый аккаунт | `d`=старый userId, `nickname`, `alt` | — |

- Номера дублируются в `src/lib/config.ts` и `relay/write-policy.py`.
- **Перенос:** `d` = старый id записи, поэтому повтор не плодит дубли, а уже перенесённое пропускается.
  `created_at` перенесённых событий — разные секунды подряд, иначе постраничное чтение по времени ломается.
  Сначала публикуется заявка, потом записи.
- **Удаление:** «надгробие» (то же `d` + тег `deleted`) плюс kind 5 с тегом `a`. Надгробие работает на любом relay.
- **Подписки:** kind 3. Старые подписки разрешаются через заявки (`#d` = старые id). Ожидающих не храним:
  клиент заново строит их из своих заявок и архива (страница «Подписки»).
- Лента на главной — новые книги без тега `legacy`, иначе перенос сотен книг забил бы ленту.

## Команды

```sh
npm run legacy                         # клон repo2 во временный каталог вне проекта → public/legacy → клон удаляется (~1 мин)
npm run relay                          # два локальных relay: 7777 и 7778 (реплика, синхронизация раз в 30 с; образ — при первом запуске)
docker build -t knigopis-node .        # образ узла целиком (strfry ~5 мин, архив repo2 ~1 мин; дальше из кеша)
VITE_RELAYS=ws://localhost:7777,ws://localhost:7778 npm run dev
npm run e2e                            # сквозной тест в системном Chrome (пишет данные — только локально)
E2E_CSP=1 node e2e/flow.mjs http://localhost:5175   # то же с CSP узла — на продакшн-сборке (vite preview, VITE_RELAYS)
python3 relay/test_write_policy.py     # проверки политики записи relay
npm run build                          # tsc + vite build → dist/
npm run release -- vX.Y.Z              # релиз на GitHub (сайт, архив); образ узла соберёт Actions
deploy/node.sh                         # главный узел: свежий образ из ghcr.io и перезапуск (после сборки в Actions)
deploy/node.sh --local                 # то же, но образ собрать здесь и отвезти (без релиза)
deploy/apply-caddy.sh                  # блок deploy/knigopis.caddy → /etc/caddy/Caddyfile (validate, бэкап, reload)
```

Проверено локально (2026-11-02), образ узла: свой HTTPS; за nginx (`nginx.conf.example` и «небрежный»
`$proxy_add_x_forwarded_for`), за Caddy и за nginx-proxy (compose-файлы как есть) — маршруты, NIP-11, WebSocket,
редирект `REDIRECT_FROM`, relay видит адрес клиента и не верит подставленному; синхронизация двух узлов (5 с);
падение Caddy/strfry → перезапуск; `docker stop` → код 0. Выдача сертификата acme-companion не проверялась.
Там же (2026-11-02): ограничения контейнера (локально; `no-new-privileges` на сервере не работает, см. выше) —
запуск во всех режимах, запись, отказ при «нехватке места», перезапуск при падении, `docker stop`; полный e2e
с CSP узла — без нарушений.
Адрес клиента проверять клиентом из «публичной» сети (`docker network create --subnet 100.64.0.0/24`):
клиент с частного адреса Docker считается доверенным прокси и подменяется адресом прокси.

Скриншоты на настоящих данных без записи в продакшн: одноразовый контейнер `knigopis-relay:dev` на свободном порту,
в нём `/app/strfry sync wss://www.knigopis.com --dir down`, и dev-сервер с `VITE_RELAYS` на него. Тестовые записи — только туда.

Модули `src/lib` можно проверять без входа и UI: на dev-сервере в Playwright
`page.evaluate(() => import('/src/lib/nostr.ts'))` отдаёт тот же экземпляр модуля, что у приложения.

## Главный узел: www.knigopis.com на bizibah

- **Сервер** `root@bizibah.com` (165.227.139.115, DigitalOcean): Ubuntu 24.04, 1 vCPU, 1,9 ГБ RAM, Docker 29.8 / Compose v2.20,
  Caddy 2.11. На сервере много других сервисов; контейнеры слушают только `127.0.0.1`.
- **Размещение** (с 2026-11-02 — образ узла; прежние статика и отдельный relay убраны):
  - `/opt/knigopis/compose.yml` (= `selfhost/compose.proxy.yml`) и `.env` с `DOMAIN=www.knigopis.com`, контейнер
    `knigopis-node-1` на `127.0.0.1:8080`, том `knigopis_relay-data` (тот же, что был у relay). Выкладка —
    `deploy/node.sh`; синхронизация выключена (известный узел — он сам). В auto mode выкладку и правки на сервере
    запускает пользователь (`! deploy/node.sh`), чтение по ssh — можно;
  - блок Caddy дописан в конец `/etc/caddy/Caddyfile` между маркерами `# >>> knigopis` / `# <<< knigopis <<<`:
    `www.knigopis.com` → `reverse_proxy 127.0.0.1:8080`; `knigopis.com` → 301 на www; `knigopis.bizibah.com` →
    301 на www, но relay (WebSocket, NIP-11) по нему ещё отвечает. Там же `/sw.js` — Service Worker, который удаляет
    себя и кеш: иначе установленное приложение брало страницы из кеша и до редиректа не доходило (проверено в Chrome).
    Сниппеты `security` (без CSP) и `logs` — общие, `knigopis_relay` — наш.

## Подводные камни

- **Лимит inotify на машине владельца — ~61 тыс. наблюдений** (`fs.inotify.max_user_watches`). За папкой следят
  Vite и Sublime Text.
  - Большие деревья файлов (клон repo2 — 44 тыс., `dist/`) в проекте не держать: клон — только временный, вне проекта;
    `dist/` удаляется после выкладки.
  - Vite не следит за `public/legacy`.
  - `/tmp` здесь — tmpfs (в памяти), поэтому большое туда тоже не класть.

- **Caddy:** матчер `header Connection *Upgrade*` чувствителен к регистру — Node/undici шлёт `connection: upgrade`
  и получал index.html. Используется `header_regexp Upgrade (?i)^websocket$`.
- **Caddy за прокси** обязан передавать relay адрес клиента: `header_up X-Real-IP {client_ip}` плюс `trusted_proxies`.
  С `{remote_host}` relay видит всех с адреса прокси и режет частоту записи всем разом. `client_ip_headers` —
  только `X-Forwarded-For` со strict: `X-Real-IP` внешний Caddy пропускает от клиента как есть.
- **Compose v2.20 на сервере** не понимает `docker compose ps --format`.
- **Playwright `route.fulfill`:** Chrome считает такую страницу пришедшей «из интернета» и не пускает её к `localhost`
  (Local Network Access, `ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS`) — нужен `--disable-features=LocalNetworkAccessChecks`.
- **Остановка процессов:**
  - `pkill -f <шаблон>` в Bash-команде убивает и саму оболочку (шаблон есть в её командной строке). Останавливать по PID.
  - У `npx vite` по PID умирает только обёртка `npx`, сам vite надо искать по порту: `ss -ltnp 'sport = :5174'`.
  - `npx <пакет>`, которого нет в проекте, ждёт подтверждения установки и вешает команду.
- **Relay** индексируют для фильтров только однобуквенные теги. Поэтому поиск заявок идёт по `#d`, а не по `legacy`.
- **`effect` в `main.tsx`** реагирует только на `account`; остальное — в `untracked`. Иначе он подписывается на
  сигналы, которые читают `ensureProfiles` и `query` (профили, список relay), и перезапускается от каждой загрузки профиля.
- **Профиль (kind 0) — одна версия на автора:** при равном `created_at` relay оставляет версию с меньшим id, вторую
  отклоняет. Поэтому новая версия — строго новее прежней (`nextTime`), и профиль публикует только одно место за раз
  (при создании аккаунта — `Login`, а не `ensureShortTag`): иначе ник терялся.
- **Без связи** `querySync` молча отдаёт пустой список — `query()` в этом случае бросает ошибку, чтобы не показать «записей нет».
- **Действия у книги** на десктопе видны по наведению (`hover: hover`), на сенсорных экранах — всегда.
  Playwright перед кликом должен навести курсор.
- **Старая ссылка `#/…`** на уже открытой странице меняет только hash — ловится `hashchange`.
- **Service Worker** регистрируется из `src/main.tsx` (`virtual:pwa-register`, autoUpdate, `injectRegister: false`).
  При `injectRegister: false` плагин сам не ставит `skipWaiting`/`clientsClaim` — они заданы в `vite.config.ts` явно.
  Без них новая версия скачивалась и ждала, пока закроют все вкладки сайта, а перезагрузка не помогала (так было
  до 2026-11-02). Теперь хватает одной перезагрузки, а открытая вкладка проверяет обновление и при переходах
  по сайту — не чаще раза в 10 минут (`checkForUpdate`). Проверка в Playwright: `page.clock.install()` +
  `fastForward('11:00')`, сборку подменять под `vite preview` (перезапуском: он не видит новых файлов).
  Архив `/legacy/*` SW отдаёт по StaleWhileRevalidate: при первом заходе после релиза новый код получает
  старую копию файла. Меняя формат файла архива, код должен понимать и старый (так с `latest.json` в v0.4.1).
- **Удаление** (NIP-09) relay не обязаны выполнять. Safari стирает хранилище неустановленного сайта через 7 дней —
  резервная копия ключа обязательна, и мы просим `navigator.storage.persist()`.
- **Логотип** — только PNG 172×42 (на retina мыльный); векторного исходника нет.
